## 教学文档与代码注释约定

- AI 可以编写、维护 Markdown；工程代码、依赖安装、运行命令和 Git 操作由用户执行，除非用户明确授权代办。
- 每个教程先写完整的目标、依赖、文件路径、实现步骤、配置衔接与验收，再带用户逐步完成。
- 代码在关键逻辑、配置作用和运行边界处写必要的中文注释，不逐行复述语法，不加入未实现能力或无关依赖。
- 注释必须符合文件语法：TS/JS 使用 //，HTML/Vue 模板使用 HTML 注释，CSS 使用块注释，Shell/YAML 使用 #。tsconfig 与 VS Code 设置可用 JSONC；package.json 等严格 JSON 在代码块外解释，不插入非法注释。
- 明确区分完整文件、替换内容与合并片段；分步修改后提供关键文件最终状态，避免漏注册、重复配置。

## 1. 技术基线

| 范围 | 选型 |
| --- | --- |

| 登录 | 短期访问令牌、可轮换刷新令牌、系统加密凭据存储 |
| AI | AI SDK Core、Provider 适配层、自建 Agent 运行核心 |

| 云端部署 | Linux、Node.js、PostgreSQL、Nginx、systemd |

初始化时核验实际兼容版本并提交锁文件。依赖随任务安装，不提前安装全部工具。

### 部署工具说明

- **Nginx**：云端入口，配置 HTTPS、反向代理 NestJS；SSE 接口关闭代理缓冲并配置合适的连接超时。
- **systemd**：Linux 系统的服务管理工具，用于服务自启动、异常重启和查看运行状态。
- **Docker Compose**：统一启动多个容器服务的工具。前期不采用，后续需要统一环境时再学习。
- **Caddy**：另一种 Web 服务与反向代理工具。本项目选 Nginx，不引入 Caddy。
- **CI**：提交代码后自动执行类型检查、测试和构建。先学会手动执行，后续再配置。

## 2. 架构边界

- 本地模式可以不登录使用；登录开启云端能力。首次云端登录需要联网。
- Electron 负责桌面与本地能力，NestJS 负责云端服务，不在每台桌面内启动 NestJS。
- renderer 通过受控 IPC 使用本地能力，不直接操作数据库、文件系统或凭据。
- main 管窗口、系统能力、IPC 和后台进程；runtime 管数据库、解析、检索与 Agent 任务。
- 本地功能不因云端断线停止；需要云端的功能明确显示网络和登录状态。
- 默认保留本地数据；上传、同步与分享分别设计范围和状态。
- 账户之间、本地访客工作区与云端工作区之间隔离数据，不自动合并。
- Redis、消息队列、独立向量数据库、多 Agent 编排在出现明确需求后再评估。

建议目录：

```text
apps/
  desktop/
    src/
      main/
      preload/
      runtime/
      renderer/
  server/
packages/
  contracts/
docs/
```

Agent 核心在进入 Agent 阶段后再建立；只有出现实际复用时才提取更多共享包。

## 4. 每次协作方式

1. 选择一个未完成任务，说明本次目标与涉及的文件。
2. 解释关键概念、数据流和实现选择，再逐步实现。
3. 执行与本次改动相符的检查，记录结果和已知限制。
4. 完成验收后再勾选任务，简要记录日期及结果。
5. 每个阶段完成并通过验收后，必须提交一次 Git，作为该阶段的可回溯基线；阶段内可按完整的小任务追加提交。
6. 提交前检查 Git 差异和验收结果，排除密钥、令牌、真实环境配置、本地数据库、用户附件、日志及构建产物；只提交本阶段相关改动，不覆盖或混入其他未完成工作。
7. Git 提交信息使用清晰的中文描述，例如 `feat(desktop): 完成第一阶段框架搭建`；在本文件记录阶段完成日期、验收摘要和提交标识。提交标识在提交完成后补记，随下次提交保存，最终阶段可记录在交付说明中。
8. 默认“提交 Git”指本地 commit；用户指定远程仓库并要求推送后，再执行 push。不自动合并或发布。
9. 遇到依赖阻塞时记录阻塞条件，不用假数据或空页面代替完成；未通过验收不标记阶段完成。
