# 造境 · Scenova 产品与技术实施方案

版本：1.0  
日期：2026-10-20  
状态：架构实施基线，尚未初始化新工程  
开发方式：手写实现，AI辅助Css样式，按阶段验收。
产品形式：Mac桌面软件

## 1. 产品目标与实施原则

造境 · Scenova 是一个以项目为上下文，贯穿资料、原型、实施、测试、问题处理、知识沉淀和组件生产的 AI 产品研发工作台。

首页以聊天组织工作；项目承载长期背景；Agent 执行具体任务；成果作为独立资产保存和复用；原型是首个深入实现的专业能力。

核心链路：创建项目 → 添加需求资料 → 引用资料和组件库 → 与产品设计 Agent 对话 → 生成原型 → 查看和调整 → 确认版本 → 后续测试、问题处理与项目交付。

### 1.1 不可变的设计约束

- 主题风格：访Codex风格+动态毛玻璃+些许动画+页面布局舒适
- 完整保留Codex设计的主题、颜色、字体、字号、圆角、阴影、边框、间距、组件外观、三栏比例。
- 保留窗口标题栏、侧栏、输入框和内容容器的既有视觉；只调整信息结构、业务内容、入口与行为。
- 参考 Codex 的三栏布局关系，不复制其项目、聊天、代码或开发任务。

### 1.2 首版范围

首版完成首页、项目、聊天、资料引用、单 Agent 执行和原型成果闭环；其余七个菜单建立导航及第二栏目录，按阶段深化。

暂不建设多人实时协作、通用 Agent 市场、多 Agent 自动协作、任意脚本执行、生产部署、复杂工作流编排、源码编辑器、无限画布和完整源码导出。

首版“实施”定位为后续业务方案和执行记录入口。自动改业务系统、运行命令和生产发布须另行定义执行环境与权限，不能由通用聊天直接获得系统执行能力。

## 2. 核心对象与关系

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 工作区 | 本机用户的数据边界 | 包含项目、全局资产和设置 |
| 项目 | 研发工作的长期上下文 | 关联聊天、资料、知识库、组件库、成果 |
| 聊天 | 围绕具体目标的持续讨论 | 可归属项目，也可独立存在 |
| 消息 | 用户输入、AI 回复及业务展示块 | 归属聊天，可关联执行任务 |
| 执行任务 | 一次可跟踪、可取消的 Agent 工作 | 固定上下文快照，产生工具记录及成果 |
| 成果 | 可独立打开和管理的业务资产 | 有类型、版本、来源和确认状态 |
| 资料 | 原始文件及可检索内容 | 关联项目与解析记录 |
| 组件定义 | 可被原型渲染器使用的注册组件 | 有版本、属性规则及适用场景 |

项目提供背景，聊天提出目标，任务执行工作，成果回到项目。消息卡片仅引用成果标识和版本，不作为成果内容的唯一存储位置。

“未归属项目”是项目标识为空的聊天集合，不建立同名虚拟项目。移入项目仅影响后续任务上下文；历史任务仍保留执行时的上下文快照。

项目默认归档；归档不删除成果和聊天。永久删除不纳入首版日常操作，后续单独设计回收站和关联数据清理规则。

弹窗字段：项目名称、项目描述、项目类型、目标平台、默认组件库、关联知识库、项目成员。

- 目标平台：Web、平板、手机、小程序；首版单选，作为生成约束。

- 后台管理项目额外显示使用顶部导航、使用左侧导航，初始均开启；其他类型保留配置但不参与生成。
- 平板、手机、小程序首版表示原型目标尺寸和交互约束，不表示生成对应平台的生产应用。

创建成功后展开项目、创建该项目空聊天、带入项目上下文。创建失败保留表单内容，避免重复点击生成多个项目。

## 4. 技术栈决策

采用本地优先的单仓库、单桌面应用、模块化架构。不在第一版启动本地 HTTP 后端，不提前拆微服务和多个业务包。

| 层次 | 确定选型 | 用途与边界 |
| --- | --- | --- |
| 语言 | TypeScript | 主进程、预加载、界面和业务模型统一类型 |
| 桌面 | Electron | 窗口、文件、系统凭据和进程管理 |
| 构建 | electron-vite + Vite | 统一组织 main、preload、renderer 构建 |
| 界面 | Vue 3，Composition API | 工作台及原型渲染 |
| 路由 | Vue Router，Hash 模式 | 项目聊天、模块列表、成果详情；适配本地应用加载 |
| 会话状态 | Pinia | 界面状态、草稿、任务投影；数据库为持久化真源 |
| UI | Naive UI | 唯一界面组件库，复用既有主题 |
| 样式 | SCSS + CSS 变量 | 复用原设计 token；禁止重新生成配色 |
| 图标 | lucide-vue-next | 沿用既有图标体系 |
| 校验 | Zod | IPC 参数、工具输入输出、成果文档校验 |
| 数据库 | SQLite + better-sqlite3 | 本地元数据、消息、任务、版本索引 |
| 数据访问 | 显式 SQL + Repository | 事务和迁移可见；首版不额外引入 ORM |
| 模型接入 | AI SDK Core + Provider 适配层 | 普通对话、流式输出、工具调用；业务不直接绑定其消息类型 |
| 消息富文本 | markdown-it + DOMPurify | 禁用原始 HTML，仅呈现允许内容；业务结果用结构化卡片 |
| 文件解析 | pdfjs-dist、mammoth、纯文本解析 | 首版支持文本 PDF、DOCX、TXT、Markdown；不执行文档内容 |
| 检索 | SQLite FTS5 + 中文应用分词索引 | 元数据筛选和关键词检索；不依赖首版向量服务 |
| 包管理 | pnpm | 提交锁文件，记录 packageManager 与 engines |
| 质量检查 | ESLint、Prettier、vue-tsc | 规范、格式、类型验证 |
| 测试 | Vitest + Playwright | 核心业务、跨进程协议及桌面关键链路 |
| 打包 | electron-builder | macOS 开发与验收优先，Windows 单独验证 |
| 后续服务端 | NestJS + PostgreSQL + S3 兼容对象存储 | 身份、团队、分享、云端资产；不属于首版本地必需依赖 |

PostgreSQL 是新云端基线；若必须接既有 MySQL 系统，在云端开工前替换该决策并维护一套迁移，不同时维护两套数据库实现。

不在方案中猜测最新版本号。初始化时核验 Node LTS、electron-vite、Electron、Vite、SQLite 原生模块和 AI SDK 的实际兼容性，完成开发运行及安装包冒烟后锁定准确版本。打包平台与 CPU 架构对应的原生依赖必须分别验证。

electron-vite 提供多进程构建组织；原生依赖需要保持外部依赖并纳入安装包，不能按普通浏览器模块打包。参考 [electron-vite 入门](https://electron-vite.org/guide/)、[生产构建](https://electron-vite.org/guide/build)、[依赖处理](https://electron-vite.org/guide/dependency-handling)。

AI SDK 作为模型调用适配，不代替任务调度、版本管理和业务权限。其文本流、工具调用能力见 [AI SDK Core](https://ai-sdk.dev/docs/ai-sdk-core/overview)。

## 5. 系统分层与进程架构

### 5.1 界面进程 renderer

负责导航、项目目录、聊天、资料选择、任务状态、成果卡片和预览。通过有限 bridge 调用应用服务。不读数据库、不读取系统文件、不保存模型密钥、不直接执行工具。

### 5.2 预加载 preload

暴露命名业务方法和事件订阅：创建项目、查询聊天、发送消息、取消任务、导入资料、读取成果等。禁止暴露通用 SQL、任意路径访问、任意 channel 调用和 shell。

订阅返回解除订阅能力，聊天切换和窗口销毁时清理监听，防止重复消息。

### 5.3 主进程 main

负责窗口生命周期、IPC 来源和参数校验、文件选择、系统凭据、应用服务入口、执行进程管理和事件转发。主进程是唯一对外能力入口，但不执行重解析与模型循环。

### 5.4 后台运行进程 runtime

采用 Electron utility process 承载任务调度、Agent 循环、文件解析、检索和数据库访问。初版一个运行进程，数据库单写入所有者；主进程通过内部消息协议转发请求。

所有持久化操作由该进程负责，避免主进程和多个 worker 同时管理连接。批量解析分批提交并限制大小；确有阻塞证据后，再拆解析 worker。

运行进程退出时主进程发出服务不可用事件并按有界策略重启；恢复数据库中非终态任务，标记为中断，等待用户重试，不无声重新执行有副作用工具。

### 5.5 依赖方向

界面 → bridge → 应用服务 → 领域模型与端口 → 数据库、文件、模型等适配器。

领域模型不依赖 Vue、Pinia、Electron 和模型 SDK。应用服务组织用例；Repository 负责数据访问；工具调用同一套应用服务，避免单独维护一套 Agent 专用业务逻辑。

Electron 隔离配置采用 contextIsolation 开启、nodeIntegration 关闭、sandbox 开启；preload 仍须限制暴露面。依据 [Electron 进程沙箱文档](https://www.electronjs.org/docs/latest/tutorial/sandbox)。

## 6. 工程目录

以下为目录职责，不要求一次创建所有空目录。

- scenova/
  - docs/：产品说明、架构决策、协议、视觉基准及验收清单。
  - resources/：应用图标、安装包资源、内置组件库元数据。
  - migrations/：按序号管理的 SQLite 迁移。
  - src/main/：窗口、IPC、凭据、运行进程宿主。
  - src/preload/：类型化 bridge 和受控事件订阅。
  - src/runtime/：任务调度器、进程消息入口、生命周期。
  - src/application/：项目、聊天、资料、成果等用例服务。
  - src/domain/：领域模型、状态转换、Repository 和 Provider 端口。
  - src/agent/：上下文构建、Agent 定义、工具注册、执行循环。
  - src/infrastructure/：SQLite、文件、解析器、模型、检索适配器。
  - src/shared/：跨进程 DTO、错误码、事件协议、边界校验。
  - src/prototype/：页面协议、组件注册、编辑操作、版本迁移。
  - src/renderer/app/：入口、路由、全局 Provider、工作台布局。
  - src/renderer/features/：home、projects、chat、materials、artifacts、settings 以及后续专业模块。
  - src/renderer/prototype/：Vue 原型渲染器和编辑视图。
  - src/renderer/components/：工作台公共界面组件。
  - src/renderer/styles/：原设计全局样式、主题 token 和 Naive UI 映射。
  - tests/：领域测试、应用服务集成测试、桌面关键流程。

规则：业务组件按功能就近维护；只有两个以上模块实际复用时才提到公共目录。shared 不存业务 Store，不变成杂物目录。具备第二个使用方后再评估抽取独立 packages。

| settings / schema_migrations | 非敏感配置及数据库迁移记录 |

团队成员、分享令牌、云端账户在团队阶段引入；首版不建立假账户系统。模型凭据不进入 settings。

统一使用全局唯一标识和 UTC 时间存储，界面按用户时区展示。顺序依赖数据库序号，不依赖时间戳唯一性。启用外键；聊天消息使用聊天标识与顺序号唯一约束。

### 7.2 文件组织

数据库与附件存放于 Electron userData 下专属工作区，不存入源码目录。附件由应用生成文件标识，保留原文件名作为元数据，禁止原文件名直接拼接路径。

按 assets、artifact-versions、backups、logs 等职责组织。原始文件不可变，解析结果可重新构建。文件内容使用摘要去重；实际删除必须考虑其他资料和成果引用。

保存流程：先写临时文件并原子移动，再事务提交数据库引用。异常产生的孤立文件由启动检查或定期清理处理；不能先提交指向不存在文件的“已保存”记录。

### 7.3 迁移、备份与并发

- SQLite 启用 WAL、外键和合理 busy timeout；部署时确认编译支持 FTS5。
- 数据库迁移顺序执行，迁移前生成一致性备份；失败不进入正常工作台。
- 运行时备份使用 SQLite 备份能力，配合附件清单；不只复制正在写入的数据库主文件。
- 大批量解析避免长事务；数据库操作保持短小。
- 成果编辑使用基础版本校验，旧版本提交冲突时提示用户，不覆盖新版本。
- 数据库迁移版本、成果 Schema 版本、组件版本分别维护。

## 8. Agent 执行系统

### 8.1 首版 Agent

先实现 Scenova 产品设计 Agent。Agent 定义包括稳定标识、名称、版本、系统规则、允许工具、上下文策略、模型配置和预算上限。

不让每个菜单对应一个独立模型进程。后续的实施、测试、知识 Agent 通过定义和工具集扩展，共用执行运行时。

### 8.2 任务流程

1. 保存用户消息，并以客户端请求标识去重。
2. 创建任务，固定项目配置、Agent 版本、显式引用及成果版本。
3. 根据任务检索资料，构建预算内上下文。
4. 调用模型，向界面发送流式文本和可理解的执行状态。
5. 校验工具参数和访问范围，调用业务服务。
6. 工具结果以结构化内容返回模型，不执行模型生成脚本。
7. 校验成果，保存版本，再发出可打开的成果卡片。
8. 完成任务并生成通知；失败记录可恢复原因。

首版限制最多 8 次工具循环，并设置可配置的总时限、上下文和输出预算；达到上限以明确原因结束。单工具耗时上限独立设置，首次调用不盲目套用同一个超时。

### 8.3 状态机

任务：排队 → 执行中 → 等待确认（可选）→ 执行中 → 已完成。

排队或执行中的任务可进入已取消；异常进入失败；进程退出后的非终态任务进入已中断。终态不能被迟到的模型响应改回执行中。

成果：草稿、等待确认、已确认、已归档。任务完成不代表成果已确认。首版主要是任务完成后等待成果确认；只有确需外部副作用时才使用任务本身的等待确认状态。

### 8.4 工具集合

首版提供：查询项目、搜索资料、读取资料片段、查询组件、读取原型版本、生成原型、校验原型、保存新版本。

工具定义必须包含参数与结果规则、允许的项目范围、是否只读、幂等策略、超时和可取消能力。不可向模型暴露通用文件系统、shell、SQL 或运行任意代码的工具。

重复的保存请求返回同一结果；有副作用工具不因网络断开自动重放。纯读取工具允许有限次数重试。

### 8.5 事件协议与恢复

每条事件包含任务标识、聊天标识、事件序号、类型、时间和业务负载。事件类型覆盖任务状态、文本增量、工具开始与结束、成果创建、用量与错误。

关键状态持久化后才通知界面；文本增量合并为批次落库，避免每个字符一次数据库写入。界面以序号去重，重新订阅后从上次序号补齐，最后查询任务快照校正。

取消由运行时先记录取消状态，再中止模型请求和可取消工具；取消后不创建新成果。已经提交的独立成果保留并明确提示。进程中断保留已收到文本，标记回复未完成。

## 9. 上下文、资料与检索

上下文优先级：平台规则 → Agent 定义 → 当前项目约束 → 用户当前目标 → 显式引用 → 检索片段 → 必要历史摘要。

显式引用优先保留；超出预算时提示用户缩小范围。历史摘要记录来源消息范围，可重建，不取代原消息。资料作为业务输入处理，不能改变工具权限或平台规则。

首版解析支持文本 PDF、DOCX、TXT、Markdown。扫描 PDF 显示需要 OCR，后续接入；表格、图像和复杂排版解析不承诺无损。导入配置可调整的文件大小和页数上限，解析前检查，失败不影响其他资料。

中文检索在应用层分词后建立 FTS5 索引，查询使用同一规则；不能默认 SQLite 内置 tokenizer 已提供完整中文分词。结合标题、项目、资料类型和最近使用加权。后续基于评测结果增加 embedding 混合检索，首版不部署独立向量数据库。

引用记录资料标识、解析版本、内容摘要、页码或段落、任务标识。资料更新后旧任务仍指向原版本；被删除或权限变化的资料不得继续作为新任务输入。

## 10. 原型能力与成果体系

### 10.1 页面协议

页面文档包含协议版本、页面元信息、节点树、模拟数据和白名单交互。节点包含唯一标识、注册组件标识、组件版本、属性、子节点及必要的布局约束。

AI 生成结构化页面文档，渲染器按照注册表显示实际组件。输出校验包括结构、属性类型、组件存在性、嵌套关系、节点数量、最大深度和事件白名单。

组件缺失显示明确占位及修复入口，不擅自换成含义不同的组件。组件版本不匹配时执行显式迁移或显示兼容性提示。

### 10.2 组件体系

区分工作台组件、布局组件和业务原型组件。业务组件注册表记录名称、版本、描述、适用场景、默认属性、属性规则、插槽、子节点限制、事件和来源组件库。

首个后台组件库覆盖页面容器、筛选栏、文本输入、选择器、按钮、数据表格、分页、表单、弹窗和详情分组。

“AI 生成组件”首版未来扩展为现有组件的声明式组合，不安装模型生成的任意 Vue 或 JavaScript。公司现有组件若需要代码接入，由开发阶段完成可信注册。

### 10.3 编辑与版本

手动编辑和 AI 修改共用文档协议与编辑操作。提供添加、删除、移动、修改属性、撤销和重做；先通过结构树和属性面板完成，再考虑拖拽。

编辑状态、选中节点、面板开关不进入页面文档；预览表单输入、筛选和分页模拟状态不污染已保存文档。

已保存版本不可变。编辑草稿自动保存，用户确认或 AI 调整完成时形成新版本。生成时固定基础版本，若任务完成前用户已修改，保留为候选分支供应用，不覆盖当前稿。

### 10.4 分享

本地阶段支持查看和本地导出，分享入口显示需要启用分享服务，不生成无效链接。云端阶段上传指定成果版本的静态预览快照，分享配置包括有效期、撤销和访问范围。

默认不上传项目附件、完整聊天和内部资料。分享内容与源项目数据分开授权。在线分享是显式发布动作，由用户在设置界面确认。

## 11. IPC、凭据与日志

IPC 请求统一使用请求标识、命名操作、可序列化参数和结构化结果。错误码至少包括参数无效、对象不存在、版本冲突、解析失败、模型不可用、额度或速率限制、任务取消、存储失败。

渲染进程不接收原始异常栈。内部日志保留请求和任务标识，界面显示可操作的错误说明。

模型密钥通过 Electron safeStorage 保护后保存，仅主进程解密并按需传给运行进程；检查平台加密能力，不在不可用时静默改存明文。日志默认排除密钥、原始附件和完整模型请求。

Markdown 禁用原始 HTML并清理输出，外链使用受控打开方式。预览只执行可信注册组件和白名单交互；应用设置内容安全策略、校验 IPC 来源、限制导航和新窗口。

这些约束属于产品的执行边界，不在普通聊天流程中增加无关确认弹窗。

## 12. 后续云端架构

桌面客户端通过 HTTPS 访问 NestJS 服务；服务端使用 PostgreSQL 保存用户、团队、权限、分享和资产索引，S3 兼容存储保存公开范围内的成果与附件。

客户端不直接连接云数据库。身份授权、分享访问判断、团队成员校验在服务端执行。

先做固定版本发布和团队资产下载，再做项目同步。同步需单独设计客户端变更记录、版本冲突、删除传播、离线重试与账户切换；本地库加云数据库不等于自动具备同步能力。

本地个人模式的模型密钥由用户持有；团队托管模型时由服务端模型网关持有团队凭据，两种模式分别管理费用和用量。

| 阶段 | 交付内容 | 验收条件 |
| --- | --- | --- |
| P0 设计与工程基线 | 保存视觉基准、锁定依赖、桌面构建、bridge、运行进程、数据库迁移 | 开发窗口与安装包均能启动，数据库读写可用，原生模块加载通过 |

| P2 本地数据闭环 | 项目聊天增改归档、草稿、资料导入解析、检索引用 | 重启后恢复数据；坏文件失败可重试；未归属聊天可移入项目 |
| P3 真实 Agent 对话 | Provider、上下文、流式消息、任务队列、停止重试、恢复 | 引用真实资料；界面不阻塞；切换聊天不中断；取消后不出现迟到成果 |

| P5 发布与扩展 | 分享服务、团队账户，按需求接知识、测试、问题等 | 固定版本可分享和撤销；权限有效；各模块复用项目与成果体系 |

P1 的演示只证明界面和交互结构；P4 才是本地首版业务可用的完成点。团队共享以 P5 为准。

每阶段交付对应的架构决策、数据迁移、错误状态和验证记录。避免先把八个模块全部做成空壳深页面，再回来补主链路。

## 14. 测试与验收

### 14.1 必要自动化

- 领域测试：任务合法状态转换、取消终态、上下文预算、文档校验、版本冲突、编辑撤销。
- 数据集成测试：迁移回滚策略、外键和唯一约束、事务、幂等请求、版本写入和一致性备份恢复。
- Agent 集成测试：使用确定性假 Provider 覆盖工具失败、超时、无效结构、重复调用、循环上限和取消。
- 桌面端关键流程：新建项目、创建聊天、导入引用、流式回复、查看成果、继续调整、重启恢复。
- 安装包冒烟：SQLite 原生模块、文件解析资源、运行进程路径、凭据能力、开发和生产资源加载。

真实模型只做少量代表性验收，记录输入、模型配置与结果，不能依赖随机回答作为固定单元测试断言。

### 14.2 视觉验收

在相同系统、窗口尺寸、缩放与字体条件下对比基准截图。检查标题栏、三栏边界、输入框位置、主题 token 和既有组件样式。

文本内容变化允许产生正常换行；不以文本变化为理由调整全局字号、间距或侧栏比例。按钮图标有可访问名称，键盘可操作项目展开、菜单和弹窗，弹窗关闭后恢复焦点。

### 14.3 完整业务验收场景

1. 创建客户管理系统，选择后台管理、Web、公司后台组件库。
2. 导入客户管理需求文档，解析成功后引用。
3. 新建“生成客户列表原型”聊天并发送指定需求。
4. 显示真实读取、组件查询和生成状态。
5. 产生可打开的客户列表原型，包含筛选、表格、新建、批量操作和分页。
6. 继续调整，产生新版本；原版本仍可查看。
7. 确认某个版本，重启应用后项目、聊天、引用、成果和确认记录完整恢复。
8. 停止生成、断网、解析失败和磁盘写入失败均有明确反馈，不假报成功。
