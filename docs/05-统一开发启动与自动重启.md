# 第 05 项：统一开发启动与自动重启

日期：2026-10-28。状态：操作文档已准备，等待你手写与验证。

## 本项目标

04 已由你反馈完成。本项把手动双终端操作合并为根目录的一条 pnpm dev：

1. 启动 Vite，等待监听完成。
2. 编译 main 与 preload，两个入口都成功后启动 Electron。
3. Vue 修改交给 Vite 热更新；main/preload 修改后重新编译并重启 Electron。
4. Ctrl+C 或 Electron 主动退出时，关闭本次启动的进程、服务器和文件监听。

AI 只维护 Markdown；工程文件、安装、运行和 Git 操作由你完成。下面路径相对仓库根目录，命令也从根目录运行。

本项不添加依赖，不引入 electron-vite、concurrently、nodemon 或额外 watcher。继续使用已安装的 Vite、esbuild、Electron 与 Node 24。

## 第一步：理解启动脚本

新脚本运行于本机 Node，负责协调进程，不属于 Electron main，也不能导入到 renderer。

选择 scripts/dev.mjs：.mjs 明确使用 ES Module，Node 可直接执行，不必先编译启动工具本身。应用的 main/preload 仍是 TypeScript，输出仍为 .cjs。

当前验收平台为 macOS arm64。Node 的目录递归监听用于本项已有的 main/preload 源码；未来跨目录共享代码、其他平台和安装包运行不能仅凭本项通过就视为已验证。

## 第二步：创建启动脚本

先手动创建目录 `apps/desktop/scripts`，再新建 `apps/desktop/scripts/dev.mjs`。

以下是完整文件。可以分成导入与状态、进程管理、编译、监听与退出几部分手写，但最终只保留一份代码，不重复追加同名函数。

```js
import { watch } from 'node:fs'
import { spawn } from 'node:child_process'
import { fileURLToPath } from 'node:url'
import { resolve } from 'node:path'
import { createServer } from 'vite'
import { build } from 'esbuild'
import electronPath from 'electron'

// 所有路径锚定脚本自身，避免依赖终端当前目录。
const desktopDir = fileURLToPath(new URL('../', import.meta.url))
const watchers = []
const expectedStops = new WeakSet()
let server
let electronProcess
let debounceTimer
let revision = 0
let stopping = false
let shutdownTask

// 将构建与重启串行化，防止快速保存时同时启动多份 Electron。
let buildQueue = Promise.resolve()

async function stopElectron() {
  const child = electronProcess
  if (!child) return

  if (child.exitCode !== null || child.signalCode !== null) {
    if (electronProcess === child) electronProcess = undefined
    return
  }

  expectedStops.add(child)

  await new Promise((resolveStop, rejectStop) => {
    let forceTimer
    const finish = (error) => {
      clearTimeout(killTimer)
      clearTimeout(forceTimer)
      child.removeListener('close', onClose)
      if (error) rejectStop(error)
      else resolveStop()
    }
    const onClose = () => finish()

    // 先请求终止，仍未退出再结束这一份子进程；不用 killall。
    const killTimer = setTimeout(() => {
      child.kill('SIGKILL')
      forceTimer = setTimeout(() => {
        finish(new Error('Electron 未能退出，请检查本次进程'))
      }, 2000)
    }, 3000)

    child.once('close', onClose)
    child.kill('SIGTERM')
  })

  if (electronProcess === child) electronProcess = undefined
}

function startElectron() {
  // 某些编辑器带有此环境变量，不能让桌面可执行文件按纯 Node 模式运行。
  const env = { ...process.env }
  delete env.ELECTRON_RUN_AS_NODE

  // electronPath 是 Electron 可执行文件路径，直接启动它，不增加 shell 层。
  const child = spawn(electronPath, ['.', '--renderer-dev'], {
    cwd: desktopDir,
    env,
    stdio: 'inherit',
    shell: false,
  })
  electronProcess = child

  child.once('error', (error) => {
    // 启动失败也要回收 Vite 和监听器。
    if (electronProcess === child) electronProcess = undefined
    console.error('[dev] Electron 启动失败', error)
    void shutdown(1)
  })

  child.once('exit', (code, signal) => {
    if (electronProcess === child) electronProcess = undefined
    if (expectedStops.has(child) || stopping) return

    // Cmd+Q 是主动退出，不立即重新拉起；崩溃也结束本轮开发会话。
    console.info(`[dev] Electron 已退出：code=${code}, signal=${signal}`)
    void shutdown(code === 0 ? 0 : 1)
  })
}

async function rebuildAndRestart(currentRevision) {
  if (stopping || currentRevision !== revision) return
  console.info('[dev] 编译 main 与 preload…')

  const common = {
    absWorkingDir: desktopDir,
    bundle: true,
    platform: 'node',
    format: 'cjs',
    target: 'es2022',
    external: ['electron'],
    logLevel: 'info',
  }

  // 等两个构建都结束；一个失败时也不能让另一个在后台继续写文件后重启。
  const results = await Promise.allSettled([
    build({
      ...common,
      entryPoints: ['src/main/index.ts'],
      outfile: 'dist/main/index.cjs',
      tsconfig: 'tsconfig.main.json',
    }),
    build({
      ...common,
      entryPoints: ['src/preload/index.ts'],
      outfile: 'dist/preload/index.cjs',
      tsconfig: 'tsconfig.preload.json',
    }),
  ])

  if (results.some((result) => result.status === 'rejected')) {
    // esbuild 已打印具体错误；保留现有窗口，修正并保存后继续尝试。
    console.error('[dev] 构建失败，本次不重启；修正代码后保存以重试')
    return
  }

  if (stopping || currentRevision !== revision) return
  await stopElectron()

  // 等待旧进程退出期间可能又保存了代码，旧结果不再启动。
  if (stopping || currentRevision !== revision) return
  startElectron()
}

function requestBuild() {
  if (stopping) return
  const currentRevision = ++revision
  clearTimeout(debounceTimer)

  // 合并短时间内的保存事件；真正的构建仍按队列串行执行。
  debounceTimer = setTimeout(() => {
    buildQueue = buildQueue
      .then(() => rebuildAndRestart(currentRevision))
      .catch((error) => {
        console.error('[dev] 开发流程失败', error)
        void shutdown(1)
      })
  }, 150)
}

async function boot() {
  server = await createServer({
    configFile: resolve(desktopDir, 'vite.config.ts'),
    // JS API 从根仓库执行时也不误用根目录下的 src/renderer。
    root: resolve(desktopDir, 'src/renderer'),
  })
  if (stopping) return

  // listen 返回后才安排桌面构建与启动，不用猜固定等待几秒。
  await server.listen()
  if (stopping) return
  server.printUrls()

  for (const relativePath of ['src/main', 'src/preload']) {
    const watcher = watch(resolve(desktopDir, relativePath), { recursive: true }, requestBuild)
    watcher.on('error', (error) => {
      console.error('[dev] 文件监听失败', error)
      void shutdown(1)
    })
    watchers.push(watcher)
  }

  // 类型配置改变也会影响编译选项，监听文件名而非单独文件 inode。
  const configNames = new Set(['tsconfig.main.json', 'tsconfig.preload.json'])
  const configWatcher = watch(desktopDir, (_event, filename) => {
    if (filename && configNames.has(filename.toString())) requestBuild()
  })
  configWatcher.on('error', (error) => {
    console.error('[dev] 配置监听失败', error)
    void shutdown(1)
  })
  watchers.push(configWatcher)

  requestBuild()
}

function shutdown(exitCode = 0) {
  // 信号、退出、错误可能几乎同时发生，只执行一次清理。
  if (shutdownTask) return shutdownTask
  stopping = true
  clearTimeout(debounceTimer)

  shutdownTask = (async () => {
    // 等待启动完成，避免创建中的服务逃过清理。
    await startup.catch(() => {})
    for (const watcher of watchers) watcher.close()
    await buildQueue

    // 某项关闭失败也继续尝试关闭另一项。
    const results = await Promise.allSettled([
      stopElectron(),
      server ? server.close() : Promise.resolve(),
    ])
    for (const result of results) {
      if (result.status === 'rejected') {
        console.error('[dev] 清理失败', result.reason)
        exitCode = 1
      }
    }

    console.info('[dev] 开发会话已结束')
    process.exitCode = exitCode
  })()

  return shutdownTask
}

const startup = boot()
startup.catch((error) => {
  console.error('[dev] 启动失败', error)
  void shutdown(1)
})

// Ctrl+C 或外部正常终止时关闭本次创建的资源。
process.once('SIGINT', () => void shutdown(0))
process.once('SIGTERM', () => void shutdown(0))
```

### 逐段理解

| 部分                      | 为什么这样写                                        |
| ------------------------- | --------------------------------------------------- |
| createServer + listen     | 复用 Vite 配置，确认服务就绪后再启动窗口            |
| absWorkingDir 与绝对 root | 脚本路径与工作目录分开，构建不会输出到仓库错误位置  |
| Promise.allSettled        | main/preload 可并行编译，但两项都结束才判断是否重启 |
| revision 与 debounce      | 保存合并，过期构建不启动窗口                        |
| buildQueue                | 构建与进程重启串行，避免旧进程尚未退出就开新进程    |
| expectedStops             | 区分脚本为了重启主动结束 Electron，与用户 Cmd+Q     |
| shutdownTask              | 退出清理幂等，避免信号和退出事件重复关闭资源        |

构建语法错误后保留旧窗口，所以旧窗口不代表新代码已生效；终端错误修正并保存后才应用新版本。运行时崩溃与语法错误不同，运行时退出会结束整轮开发，修正后重新 pnpm dev。

main/preload 重启会丢失当前内存状态，这是本阶段正常行为。不要为了保留测试按钮状态而在本项提前设计数据持久化。

## 第三步：添加脚本检查与统一入口

在 desktop package.json 的 scripts 中新增：

```json
"dev": "node scripts/dev.mjs",
"check:dev-script": "node --check scripts/dev.mjs"
```

保留 04 的所有手动构建、启动、renderer、类型检查命令，它们仍可用于单独诊断。node --check 只检查 JavaScript 语法，不执行脚本。

将 desktop 的 typecheck 更新为以下内容，确保原四个检查没有遗漏：

```json
"typecheck": "vue-tsc --project tsconfig.json && tsc --project tsconfig.tools.json && tsc --project tsconfig.main.json && tsc --project tsconfig.preload.json && pnpm check:dev-script"
```

根 package.json 的 scripts 新增：

```json
"dev": "pnpm --filter @elabtable/desktop dev"
```

这是严格 JSON 字段片段，合并到已有 scripts 内，不创建第二份 scripts。根 check 仍保留类型、ESLint、格式三项。

本项 .mjs 接受语法检查与 ESLint，不宣称已经通过 TypeScript 类型检查；如果后续脚本扩大，再评估 checkJs 或独立工具工程，当前不安装 tsx 来启动此文件。

## 第四步：扩展 ESLint 的 Node 环境

在根 eslint.config.js 中原有 main 的 Node 环境配置，将 files 改为以下数组，其他内容不变：

```js
// Node 环境只作用于主进程和开发脚本，不扩散到 renderer/preload。
files: ['apps/desktop/src/main/**/*.ts', 'apps/desktop/scripts/**/*.mjs'],
```

该片段是原配置对象的 files 字段，不是独立配置文件。原有 globals: globals.node 保留，prettier 仍放最后。开发脚本使用 Node API，不能错误地配置成浏览器全局。

先执行下列检查，不启动项目：

```bash
# 复制执行时只选命令行，zsh 交互终端可能不接受粘贴的注释行。
pnpm --filter @elabtable/desktop check:dev-script
pnpm check
```

如果仅有格式提示，先审阅影响范围再运行 pnpm format，之后重新检查。其他错误按文件与行号处理，不关闭规则。

## 第五步：首次一键启动

退出 04 的 Electron，用 Ctrl+C 停止原 Vite。必须先释放 5173；本项不会自动杀死占用端口的其他进程。

根目录运行：

```bash
# 启动开发会话，终端保持运行，不必再开 Vite 或手动编译。
pnpm dev
```

预期：打印 Vite 地址 → 打印 main/preload 构建结果 → 打开 Electron。顺序依赖完成状态，不使用固定几秒的延时猜服务是否启动成功。

pnpm dev 不会自动执行完整 pnpm check，避免把每次热更新变成全工程检查。需要检查时在另一个终端运行；Vite 和 esbuild 构建均不能替代类型检查。

## 第六步：验证更新与失败恢复

| 操作                         | 预期行为                                               |
| ---------------------------- | ------------------------------------------------------ |
| 修改 HomeView.vue 的提示文字 | Vite 更新内容，不重启整个 Electron                     |
| 修改 main 的初始 width       | 编译成功后重启窗口，尺寸变化                           |
| 修改 preload 日志            | 编译成功后重启，控制台显示新日志                       |
| 短时间连续保存 main/preload  | 最终启动最新成功版本，不出现多份应用窗口               |
| 在 main 写入临时语法错误     | 终端显示错误，旧窗口保留；不启动错误构建               |
| 修正错误并保存               | 编译成功后重启，恢复开发                               |
| 首次启动时 main 已有语法错误 | Vite 和监听继续运行，没有 Electron；修正保存后出现窗口 |

语法错误演示只为理解恢复过程，验收后删除错误并恢复正常代码。试验用的 width 或提示文字也按你的实际意图恢复，不把临时错误当作成果提交。

## 第七步：退出与资源清理

分别验证，两个场景之间重新 pnpm dev：

1. 终端按 Ctrl+C：Electron 退出、Vite 关闭、监听停止，终端回到提示符。
2. Electron 使用 Cmd+Q：本轮开发会话结束，不自动重新拉起窗口，也不继续留着 Vite。

macOS 点击红色关窗按钮不等于退出应用，沿用 04 的应用生命周期；仍可以点 Dock 重开。结束开发会话使用 Cmd+Q 或 Ctrl+C。

退出后再次 pnpm dev 应可使用同一端口启动。若提示端口占用，可以只读查看：

```bash
# 只查看 5173 的监听者，不终止任何进程。
lsof -nP -iTCP:5173 -sTCP:LISTEN
```

不要使用 killall node 或 killall Electron 清理，它会影响其他项目。脚本仅管理自身创建的 Electron，关闭 Vite 使用其 API；当前不扩展成跨平台通用进程树管理器。

Ctrl+Z 会挂起任务，不是清理退出。如果终端提示 suspended，先用 jobs 查看，再将自己的对应任务用 fg 恢复后 Ctrl+C；不要叠加启动多份开发会话。

## 第八步：明确监听范围

本项自动监听：main/preload 目录中的文件与子目录，以及 tsconfig.main.json、tsconfig.preload.json。

修改 dev.mjs、根 tsconfig.base.json、package.json、依赖、ESLint 配置后，先退出并重新启动。Vite 配置按其服务机制处理，但涉及开发端口时必须同步检查 main 的固定地址，再重启整轮开发。

本项 main/preload 尚未导入工作区外部共享源码；06 建立 contracts 时，要把实际共享源码目录加入监听并验证，不能声称 esbuild 的一次 build 会自动追踪所有后续文件变化。renderer 的文件依赖仍由 Vite 自己处理。

本项不抽取 04 的生产构建参数：修改入口、external 或 target 时，需同时检查 package.json 里的构建命令与本脚本 common。出现实际复杂度后再提取共用构建配置，避免默默让开发与生产参数分叉。
