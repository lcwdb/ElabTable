### 打包器下载工具的版本约束

electron-builder 26.18.0 的 app-builder-lib 会使用 ElectronDownloadCacheMode，但其依赖范围 ^3.0.0 也允许不提供该导出的 @electron/get 3.0.0。若锁文件选中 3.0.0，制作 ZIP/DMG 会出现 Cannot read properties of undefined (reading 'ReadWrite')。

本次已核对 3.1.0 包中提供该枚举，且满足声明范围。根 pnpm-workspace.yaml 顶层加入：

```yaml
# 仅约束打包器的下载依赖，不替换 Electron 45 自身的 @electron/get 5.x。
overrides:
  'app-builder-lib@26.18.0>@electron/get': 3.1.0
```

保留已有 packages、allowBuilds、engineStrict 等字段；有 overrides 时只合并这一项，不重复创建同名顶层字段。

```bash
# 更新解析结果与锁文件，不手改 node_modules 或锁文件。
pnpm install

# 查看打包器的下载依赖已解析到 3.1.0；Electron 自身的 5.x 可以同时存在。
pnpm --filter @elabtable/desktop why @electron/get
```

这解决的是制作压缩包之前的下载工具 API 错配，不保证后续网络下载、系统签名或 DMG 操作不会遇到独立问题。更新 builder 版本时重新评估此约束。

## 第四步：创建打包配置

新建 `apps/desktop/electron-builder.yml`，完整内容：

```yaml
# 应用身份沿用工程约定，正式发布后不要随意更换。
appId: io.github.lcwdb.elabtable
productName: ElabTable

# 与 desktop 的 Electron 依赖保持一致。
electronVersion: 45.0.0

directories:
  # 相对 apps/desktop，避免与源码编译目录混在一起。
  output: release

# 精确收集编译结果，不把整个仓库、教程或原始参考资料复制进去。
files:
  - dist/**/*
  - package.json

# ASAR 是应用文件归档，不是加密或源码保密机制。
asar: true

# 当前业务依赖不含原生扩展；后续接 SQLite 时重新配置并验收。
npmRebuild: false

# 由 builder 替换这些占位符，不是 Shell 环境变量。
artifactName: '${productName}-${version}-${arch}.${ext}'

mac:
  category: public.app-category.developer-tools
  target:
    - target: dmg
      arch:
        - arm64
    - target: zip
      arch:
        - arm64
  # 本机开发验收采用临时签名，不选择你机器上的正式发布证书。
  identity: '-'
  # 此阶段未配置 Developer ID 与公证凭据，不请求 Apple 公证。
  notarize: false
```

说明：

- files 控制应用文件，打包器还会按依赖关系处理生产依赖。devDependencies 不应作为应用业务依赖进入安装包；当前 Vue 和 Zod 的实际使用代码已由打包器编译。
- 本次允许默认 Electron 图标作为明确占位，不创建空 icon 文件，也不配置不存在的图标路径。正式图标作为独立设计任务完成后再接入。
- 不配置 publish，不配置签名密码或账号信息。目录 release 已被现有 .gitignore 忽略。
- 不猜最低 macOS 版本；本次只证明当前系统可运行，后续对外声明支持范围前须结合 Electron 45 官方要求和目标系统实测确认。

## 第五步：区分开发与生产 CSP

当前页面未声明 CSP。本项通过 Vite 的 HTML 插件为开发和构建页面生成不同策略，而不是在 HTML 手写两份冲突的 meta。

替换 `apps/desktop/vite.config.ts` 为以下完整内容：

```ts
import { defineConfig } from 'vite'
import type { Plugin } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig(({ command }) => {
  // 开发允许本机 HMR 连接和 Vite 注入的样式；构建页面不需要网络。
  const developing = command === 'serve'
  const csp = [
    "default-src 'none'",
    "script-src 'self'",
    developing ? "style-src 'self' 'unsafe-inline'" : "style-src 'self'",
    "img-src 'self' data:",
    "font-src 'self'",
    developing ? "connect-src 'self' ws://127.0.0.1:5173" : "connect-src 'none'",
    "object-src 'none'",
    "base-uri 'none'",
    "form-action 'none'",
    "frame-src 'none'",
  ].join('; ')

  const cspPlugin: Plugin = {
    name: 'elabtable-csp',
    transformIndexHtml() {
      // 类型由 Plugin 提供；放在文档头部，先于页面脚本加载。
      return [
        {
          tag: 'meta',
          attrs: { 'http-equiv': 'Content-Security-Policy', content: csp },
          injectTo: 'head-prepend',
        },
      ]
    },
  }

  return {
    // 包脚本在 desktop 执行；05 的 JS API 会显式覆盖成绝对 root。
    root: 'src/renderer',
    base: './',
    plugins: [vue(), cspPlugin],
    server: {
      host: '127.0.0.1',
      port: 5173,
      strictPort: true,
    },
    build: {
      // 相对 renderer root，实际输出 apps/desktop/dist/renderer。
      outDir: '../../dist/renderer',
      emptyOutDir: true,
    },
  }
})
```

原 index.html 不需要再加同名 CSP meta。构建后的 HTML 才是验收对象；preview 展示已有构建，不会将生产策略重新转换为开发策略。

当前生产页没有 fetch、WebSocket、内联 style 或 iframe，所以采用这个范围。后续接入 Naive UI、云端、图片预览等真实需求时，按实际资源与域名更新；不要为了消除错误一次加入 *、unsafe-eval 或把所有开发策略带进生产。

IPC 不通过网页网络请求，connect-src 'none' 不阻止 contextBridge 调用。CSP 也不能代替 06 的来源和参数校验。

## 第六步：限制未使用的系统权限

main/index.ts 的 Electron import 中加入 session，保留原导入：

```ts
// 保留已有 app、BrowserWindow、dialog，新增 session。
import { app, BrowserWindow, dialog, session } from 'electron'
```

将原 app.whenReady().then(createWindow).catch(reportStartupError) 替换为：

```ts
// 在创建窗口前设置当前默认 session 的权限策略，进程内只设置一次。
app
  .whenReady()
  .then(async () => {
    session.defaultSession.setPermissionRequestHandler((_webContents, _permission, callback) => {
      // 当前业务不使用摄像头、麦克风、地理位置等浏览器权限。
      callback(false)
    })
    session.defaultSession.setPermissionCheckHandler(() => false)
    await createWindow()
  })
  .catch(reportStartupError)
```

保留 window 的 sandbox、contextIsolation、nodeIntegration 设置，以及导航、新窗口限制。权限策略是当前功能范围，未来有真实需要时按来源与权限类型细化，不让通用聊天直接获得系统能力。

保留 useDevServer 的 !app.isPackaged 条件：安装包即使带 --renderer-dev 参数也不能改为连接开发服务器。当前不创建 webview、远程页面或额外窗口。

## 常见问题

| 现象                     | 先检查                                                                        |
| ------------------------ | ----------------------------------------------------------------------------- |
| Electron 下载慢          | 已安装运行时路径与 electronDist；勿把更换 npm registry 当作二进制下载必然加速 |
| 无 Developer ID          | 本项明确 ad-hoc，不需要现在配置正式证书                                       |
| 默认图标提示             | 当前允许作为占位；不要引用不存在的 icon 文件                                  |
| .app 找不到入口          | main 字段、files 是否收集 dist/main/index.cjs                                 |
| preload 加载失败         | .cjs 输出、归档资源路径、是否误把 Zod external                                |
| IPC 显示 FORBIDDEN       | 实际 file URL 与 06 计算的入口是否一致，不删除来源校验                        |
| 页面样式/脚本被 CSP 拒绝 | 具体资源、开发还是构建策略，是否加入了新组件或内联样式                        |
| DMG 打不开或系统阻止启动 | 完整构建与签名错误、系统提示；不全局禁用系统保护                              |
| 安装后看见旧版本         | 退出旧实例，确认 Applications 与 release 中的包不是混着运行                   |
